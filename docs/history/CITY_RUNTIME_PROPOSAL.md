「编辑 / 运行」切换控制模拟；选中人物或设施进入当前 Codex 上下文，局部修改、绑骨或调整动作后
在原位置更新，再恢复城市运行。其他同工程任务同步看到已提交版本；不同 worktree 保持独立。

完整导入指完整场景清单、摆放关系、源资产与运行配置可恢复，不要求全部高模同时驻留显存。
同一运行预览中的走路、开门、驾驶等行为复用 Cubely 逻辑；城市行为编辑的能力按验证结果逐项开放。

## 建议实现

1. **完整城市包 + 按实例修改记录。** 工程新增可选城市场景文档，记录源包哈希、坐标约定、
   稳定实例 ID、资产引用、布局与运行配置。变更写版本化覆盖记录，源包不直接改写。
   用户城市素材留在工程素材目录，通用插件不打包整城素材。
2. **单视口运行适配。** 增加 Cubely adapter，将 scene/camera、暂停、固定步进和可编辑对象注册
   接到现有 Studio。renderer、resize、资源释放和帧调度只由一个所有者管理。
   场景总览、对象隔离、骨架检查和运行预览使用同一工作区。
3. **场景规模与局部编辑分开。** 整城维持分区、InstancedMesh 和按距离加载；选中对象才调入
   现有精细编辑与 Blender 回填路径。不把全城每根树枝展开为普通 workbench 对象，也不靠
   取消当前 500 对象上限解决场景规模问题。列表按逻辑对象分页，AI 按需查询。
4. **修改作为一次提交。** 暂停模拟，准备候选资产及受影响碰撞块、障碍/交互索引，验证后整体
   替换。失败保留上个版本；迟到请求做对象版本检查。材质修改无需重建碰撞；移动、缩放、
   换形状必须更新碰撞和交互位置。原有路径无效时重算或明确停止该行为。
5. **人物状态单独处理。** 持久化出生点、布局、动作配置；运行中的位置、速度与瞬时姿态不逐帧
   写工程。重绑骨架后重建 CharacterActor 并校验骨骼语义；恢复到可兼容状态，不沿用旧骨索引。
6. **复用任务协作。** 场景实例接现有 scope/租约/版本/撤销；同工程提交广播，运行进度为每个
   预览的临时状态。多个任务共同编辑资产，不要求它们逐帧同步同一场驾驶或 NPC 模拟。

取舍：接入运行时需要新增场景存储与 adapter，并改造城市生成时的实例/碰撞映射；成本高于静态
整城导入，但能满足修改后继续运行。仅导出整城 GLB 可用作观察快照，无法保存 NPC、碰撞和交互逻辑。

## 实施顺序与验收

1. 在独立工程载入完整城市，输出源清单、实例数量、缺失资源与坐标检查；保留现有用户工程。
2. 单视口编辑/运行切换，检查 renderer 数量、帧循环、资源释放、场景往返保存及加载失败恢复。
3. 选中一个设施移动和替换；验证画面、碰撞命中和交互入口一起变化，原位置不残留旧碰撞。
4. 选中一个人物局部修缮/绑骨后回填；验证实例身份和行为绑定，实际观察站立、行走和交互姿态。
5. 同源实例隔离、多任务同步、同件冲突、撤销及 worktree 分支；失败候选不改变正在使用的版本。
6. 跨区域走动及驾驶烟测，记录首屏时间、帧耗时分位数、资源数、长任务和 resize 行为。
   单独记录浏览器测试与原生 Codex 体验，不能以“没有报错”替代性能验收。

道路拓扑/地形大范围重塑、任意 NPC 剧情编辑和跨窗口锁步模拟不在上述验收中。
完整导入并保留现有行为，与开放所有城市系统的编辑器，是不同的交付范围。
