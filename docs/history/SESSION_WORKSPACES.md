# 按 Codex 任务隔离的 3D 工作台

本页保留 2026-09-22 的旧 session 工程兼容契约。2026-09-23 起，新任务采用用户确认的 [文件夹工程](../FOLDER_PROJECTS.md)：同项目普通任务共享模型，worktree 隔离；旧工程不自动迁移。零件聊天的 scope 与独立选区/撤销继续有效，见 [零件协作](../WORKTREE_COLLABORATION.md)。

## 实现

`studio_*` MCP 工具接受公共参数 `workspace_id`，AI 从当前 `CODEX_THREAD_ID` 读取并在整个任务中复用；界面从资源 URI 或 `studio_open` 的结果绑定一次，不能切换到另一任务。没有 ID 的调用拒绝执行，不再隐式连接旧全局工程。没有假定宿主的 MCP 连接 ID 就是聊天任务 ID。

每个工作台位于 `~/.print-prep/workspaces/<workspace_id>/job`，有独立后台进程、随机本机端口、令牌、工程、选择、撤销历史、建模任务及观察状态。启动使用跨进程文件锁，重复连接复用同一后台。原有专业 API 配置仍共享。

这是本机工作流隔离，不是对恶意客户端的租户权限边界；本机用户仍可直接操作文件。AI 不得将别人的任务 ID 当成自己的 ID。旧版尚未重连的 MCP 进程仍可能操作旧共享工程，新版本不会写入那个工程。

## 分支

1. `studio_workspaces(action="list")` 列出工作台的名称、revision、对象数。
2. 在尚未打开的新任务中，`fork(workspace_id=<当前任务>, source_id=<来源>, expected_revision=<来源版本>)` 复制静态编辑工程。选择、撤销、后续任务从新分支开始。
3. `merge(workspace_id=<分支>, expected_revision=<来源当前版本>)` 显式合入。将分支和来源分别与基线逐零件比较；来源同一零件有不同改动时拒绝，并列出冲突 ID。合入是可撤销的单次编辑。
4. 资产按 SHA-256 校验，创建分支时复制，不使用可写硬链接。首期不分支打印排盘、历史生成任务或外部 Blender 文件，也不自动合并几何。
5. 合入后基线仍是最初分支版本；重复应用相同结果是无操作。继续修改已经合入过的同一零件时可能冲突，应从来源新建分支。这一版没有自动 rebase。

`legacy` 代表旧 `~/.print-prep/job`，只允许作为分支来源，不允许新 MCP 工具写回。没有删除或改写旧工程。

## 更新与故障恢复

- 编辑提交后，当前可见编辑器约每 3 秒同步；复用未变资产，更新变换、材质及选择。
- 每个完成且包含 GLB 的建模任务会出现“模型已更新 / 打开模型”。也可 `studio_open(workspace_id, task_id)` 显式定位结果。其他工作台不会收到该任务的提示。
- 一个任务的中间临时文件不会逐次加载。可展示阶段应发布成完整、已完成的任务产物。
- GLB 下载与解析成功后才替换上一份模型；失败显示错误，编辑器可点击“重试加载”。较晚返回的旧加载结果不会覆盖较新的结果。
- UI 的内容哈希用于宿主缓存失效。历史 `studio-<20位hash>.html` 地址作为当前界面的兼容入口，插件更新删除旧缓存后仍可读取；这是入口别名，不承诺旧 UI 字节回放。
- 旧入口没有工作台绑定时显示重新打开提示，不将它静默绑定到任何现有任务。完整编辑器仍在右侧。

## 验证

覆盖：两个 MCP 连接并发修改独立工程；资源不能从另一工作台读出；重连保留原工程；分支新增、删除、不冲突合入、重复合入与冲突拒绝；旧工程哈希不变；旧 UI URI；编辑器和任务预览失败保留旧模型。

真实浏览器测试中，状态更新延迟 2,986 ms，完成模型可打开，另一工作台仍为零对象；损坏 GLB 不会清空已显示模型。嵌入式 MCP App 测试确认所有工具和资产请求带工作台 ID，旧入口显示恢复信息，页面异常为零。
