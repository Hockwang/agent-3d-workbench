# 零件聊天分支与 worktree 内联动（已确认）

用户希望零件右键“创建聊天分支”，session 2 修缮后 session 1 看到更新。

## 建议契约

- 共享单位是同一 worktree 下的同一个 3D 工程。聊天 session 是工程的工作视图，不复制一份模型。
- 右键带入零件 ID、工程 ID、当前版本和修缮目标，创建同目录聊天分支。它默认只可提交该零件及其拆分派生件。
- 两个会话可并行修改不同零件；同一零件只允许一个会话持有写入租约。其他会话可观察或显式创建模型分支，不会抢写。
- 一次成功编辑事务生成版本事件，所有关联界面更新模型；相机、选区和当前工具保持各自独立。
- 撤销只针对当前会话自己的操作，并检查被修改零件是否已有后续变更，不能撤销掉别人之后的成果。
- 新 worktree 创建模型分支，保持隔离；合入仍要检查零件冲突。
- 保留现有每任务独立工程，通过显式绑定加入共享工程；不将现有工程按目录自动混并。

## Codex 接入边界

MCP App 自身没有已验证的直接创建聊天 API。右键操作可通过 `ui/message` 向当前任务发送用户请求，由 Codex 调用原生 `fork_thread(environment="same-directory")`，再把零件与共享工程绑定信息带入新任务。用户点击即授权创建；不会在后台自行创建测试聊天。

## 首期验收

两个会话分别修缮 A/B 零件，双方画面更新且各自选区、镜头不变；同时修改 A 时第二个会话被拒绝；租约过期仍须校验版本；撤销不会覆盖另一会话的后续修改。不同 worktree 的工程不自动联动。

此方案将“聊天分支”和“模型分支”分开，需要调整任务身份、工程绑定、逐零件版本、租约与撤销模型，用户已于 2026-09-22 确认实施；实现契约见 WORKTREE_COLLABORATION.md。
