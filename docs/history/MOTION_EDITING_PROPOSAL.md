# 动作编辑：GPT 绑骨与 PKF 运动工程

状态：用户已于 2026-09-23 确认并要求实施；首批已接入，实际契约与验证见 [MOTION_EDITING.md](../MOTION_EDITING.md)。

## 产品行为

在 3D Studio 增加独立“动作编辑”模式，使用现有模型、选区和视口布局。
左侧切换零件/骨架树，右侧编辑动作参数、关节限位和选中通道，底部显示时间轴、
片段、播放/暂停/循环和关键帧。观察与测评负责审查，动作编辑负责创作。
AI 与人修改同一份动作工程；AI 读取结构化通道、参数、检查结果并取得实际姿态截图。

例如用户让机械臂抬高、延迟启动，或让角色抬手幅度变小，已声明为参数的部分
直接改参数；增加动作阶段或新的控制通道则编辑步骤/关键帧，不能把所有编辑都称为调参。

## 绑骨与执行分工

- Codex 当前会话中的 GPT 负责看模型、测量、确定骨点/父子结构、编写和修订绑定配置，
  调用本地 Blender 完成骨架、蒙皮及动作检查；不要求额外 GPT API。
- 参照同类产品的骨架重定向工作方式：已有合格骨架优先复用，高模必要时采用代理、
  权重回迁/局部修复，并重开最终文件验证实际形变。服务绑骨可选，不是默认依赖。
- 机械模型由 MotionForge 的 FK、关键帧和 PKF 内核驱动刚性零件。
- 人物/动物保留 Blender 骨架和蒙皮权重。PKF 表达语义控制参数与动作阶段，适配到
  骨骼姿态/控制器；需要 IK、约束或动作混合时由 Blender 求解并烘焙预览。
  现有机械单自由度关节定义不能直接替代通用角色 rig。

工作台已有 `studio/blender_ops.py` 的 rig-bind、skin-weights、motion-retarget 和
Blender 任务执行基础，但目前 rig-bind 接显式骨点并调用自动权重，不等于任意角色
已经通过自动绑骨及自然动作验收。

## 运动包与兼容

复用 MotionForge 现有导出包：manifest、零位 model.glb、joints、motion clips/events、
可选 pkf parameters/steps。以实际源码的 schema v7 为兼容基准，不能采用旧文档中的 v6。

1. 可编辑工程保留参数、公式、步骤、骨架绑定信息，以及必要的原始 .blend 和引用资源。
   参数在创作时建立；从普通 GLB 动画导入不能声称自动恢复了语义 PKF。
2. 另导出带烘焙动作的 GLB，供通用播放器/引擎使用；PKF 工程仍保留为后续编辑来源。
3. 机械部分验证 MotionForge v7 往返。角色扩展使用明确版本和能力声明，不能把
   旧 MotionForge 无法读取的字段宣称为完整 v7 兼容。
4. 实际 fps、时长、单位、轴向、零位、对象/骨骼稳定身份必须进入契约。适配
   Studio 的对象 ID 与 MotionForge 的名字引用，不能依赖运行时 UUID 或显示名唯一性。
5. 预览、导出和验证共用求值逻辑；表达式采用受限数学求值器，导入 PKF 不执行任意 JS。
   不直接将旧 new Function 求值代码搬入内嵌页面。

复用内核和导出器，不嵌入另一个 MotionForge 整页，也不接它的独立 LLM 后端。
复用前记录源版本及许可；优先沿用现有 MDE 薄适配器，避免另写一套 FK。

## 与零件聊天协作的关系

工程中的 rig 和 clip 必须具有版本与依赖。单件聊天只写授权的零件/通道；
更改跨零件的骨架拓扑或多关节动作时，事务须覆盖受影响对象并检查冲突。
局部模型替换后校验绑定仍有效，不静默把旧权重应用到变化后的拓扑。
不通过共享一个整工程 JSON 来绕过已有逐件冲突与独立撤销保护。

## 实施顺序与验收

第一批贯通同一个动作模式、机械 PKF 导入/编辑/导出、本地 GPT 绑骨入口、
骨骼动画预览和导出；用一个机械模型与一个蒙皮模型分别完成实际闭环。
随后补充复杂 IK/动作混合、接触修正和更多骨架类型，不将模板冒烟当成自然动作验收。

验收应包含：修改参数立即更新姿态；时间轴修改保存重开；导出再导入不漂移；
带模型/绑定/动作的运动包可被全新任务独立接手；全段顶点形变与关节限位检查；
抽帧图和实际播放复核；同工程并发编辑、撤销与旧绑定失效处理；窗口缩放与隐藏停绘。

## 核对依据与限制

- MotionForge `src/core/KeyframeManager.js`、`ResultPackageExporter.js`、`docs/schema/v7.md`。
- 内部记录的同类产品能力条目：只读对照能力，
  本提案未复制其私有实现或提示词。
- MDE `experiments/gpt6_waveab_comparison/motionforge_handoff_20260922/RESULTS.md`：
  单三向车运动包可以由新会话继续编辑；幅度、时间和结构编辑的修改面不同。
  MF 三次交接累计 19.11 分钟，原生 15.41 分钟，未证明稳定提速。
- MDE `motionforge_multiedit_20260922/RESULTS.md`：三案累计修改耗时下降 4.0%，
  样本有限且已知 rig；不能外推任意资产绑骨、更低 token 或稳定加速。
- glTF 蒙皮需要骨架节点、权重与 inverse bind matrices，参见
  [Khronos Skins](https://github.khronos.org/glTF-Tutorials/gltfTutorial/gltfTutorial_020_Skins.html)。

已确认的架构选择：统一动作编辑入口 + GPT 本地绑骨 + PKF 可编辑运动包 + GLB 播放交付，
同时保留机械和蒙皮各自的执行与验证逻辑。
