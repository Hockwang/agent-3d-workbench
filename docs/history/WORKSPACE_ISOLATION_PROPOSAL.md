# 会话工作台与模型分支提案

状态：用户已选择“默认独立工作台＋模型分支”；首期实现与限制见 [SESSION_WORKSPACES.md](SESSION_WORKSPACES.md)。旧共享工程原样保留。

## 当前问题

所有 MCP 连接使用 `~/.print-prep/job`，工程、选择、撤销历史和任务共享。
全工程 revision 防止过期写入，但无法阻止不同会话读取最新状态后先后改同一零件。
UI 按内容哈希寻址，更新后只接受当前哈希，已打开任务的旧地址会被拒绝。

## 推荐：默认独立工作台，显式创建模型分支

1. 每个 Codex 任务绑定持久 workspace ID。工程、选择、任务、撤销历史、当前预览分别隔离；服务配置和不可变几何资产可复用。
2. 不将 MCP 连接 ID、进程 PID 当作任务 ID。先验证宿主元数据；宿主未提供稳定标识时，工具显式携带 workspace ID，缺少绑定时拒绝有歧义的写入。
3. 复用另一任务的模型时，从指定版本创建分支，记录来源工程、基线 revision 和零件内容哈希；修改发生在分支内。
4. 合入必须显式执行并校验基线。原件已被修改则列出冲突，不自动覆盖或自动合并几何。
5. 当前共享工程保留为 legacy 来源，迁移时只创建副本/分支，不删除或悄悄重新分配现有模型。

代价：增加分支与合入概念；需要任务身份绑定、资源路由和持久化的完整隔离测试。
优势：任务间不会互抢模型、选择、撤销和界面焦点，适合并行 AI 工作。

## 备选：共享工程，按零件加写入锁

所有任务看同一工程，修改零件前获取租约，其他任务只能读或创建分支。
代价：还要处理崩溃后的锁释放、跨零件操作、撤销归属和共享界面焦点；不同任务仍可能干扰彼此的工作流。

## 模型更新体验

- 每个成功提交的编辑 revision 更新所属工作台；重复事件不重新下载模型，不强制重置相机。
- 脚本/生成任务每发布一个完整可加载的阶段产物，显示“模型已更新 / 打开模型”；不观察未完成的临时写入。
- 默认只跟随本任务的改动。用户检查旧版本或其他任务结果时显示提示，由用户打开新版本，避免抢视角。
- 对话里保留小型结果入口，编辑器仍在右侧。入口携带 workspace、模型版本和产物定位。
- 新模型加载或连接失败时保留上一份有效画面，并显示可操作的错误信息。

## 可先独立修复

旧 UI 资源跨升级兼容、全屏错误可见、预览失败保留旧模型，不依赖上述架构选择。

## 验收

两任务并行修改不同工程互不影响；分支合入冲突必须拒绝；重连恢复同一任务工程；
同一 revision 仅加载一次；失败模型不清空旧画面；插件更新后旧界面地址仍可恢复。
