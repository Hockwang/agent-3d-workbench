## 已修复

1. `studio/editor.py` 检查带贴图网格时，通过 `mesh.split` 构造所有连通子网格，每个子网格都复制贴图。
   真实约 9.5 万面模型曾使进程 physical footprint 达 96.6 GB，随后 MCP 连接断开。
   改为不带材质的几何副本，焊接 UV 缝后按 face adjacency 统计连通分量。
   同一模型检查耗时 0.169 秒；独立进程 peak memory footprint 325,321,424 字节，最大 RSS 351,092,736 字节。
   这不是 Codex 原生窗口缩放性能指标。
2. `pyproject.toml` / `uv.lock` 补齐 `lxml`，修复承诺支持 3MF 却在导入时报缺模块的问题。
   新增真实 3MF 读入、单位与 build transform 回归；先失败后通过。

## 保留的失败

- **高精度 ASCII STL 转内部 GLB：**4 件源码水密，float32 序列化使极近顶点重合；最大坐标误差约 0.000002–0.000004 mm，却产生非流形边。
  当前内部 GLB 同时承担编辑数据与显示数据，不能据此宣称无损；需要高精度几何存储或明确的导入退化保护。
- **减面：**同一历史脸件保留 50%、75%、90% 面数均被水密守卫拒绝。失败后工程完全不变，但操作没有完成。
- **Bambu 工程 3MF：**几何 3MF 中脸件有 68,001 个焊接顶点且水密；Bambu 输出工程读回为 67,999 个顶点、4 条非流形边。
  变换对账和切片 exit code 都通过，仍不足以作为保真验收；需要补充几何/拓扑门禁。

## 能力边界

17 条配方中，10 条具有所需工具，7 条仍显示 `needs_tools`。语义拆件、定位销孔、装配验证、关节运动、分色、试片和生成尚未完整接入。
保脸、装配、贴图分件、URDF、动物骨架旧测试通过，不等于能在当前工作台中完成这些管线。
本轮未重跑云端生成、GPU 分割推理、动画生成、物理仿真训练或实体打印，也未测量 Codex 原生窗口缩放。

测试框架曾因多节点 GLB 拼接顺序变化误报三个坐标差异；更正为三角形空间排序后，11 个 GLB 全部通过，原始失败记录保留。
另有旧研究环境缺少 PyMaxflow，使用临时 `uv --with PyMaxflow` 环境后 10 个测试通过；未将该依赖加入插件。
