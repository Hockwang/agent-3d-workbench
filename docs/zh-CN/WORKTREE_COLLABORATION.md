# 同 worktree 零件协作

2026-09-22 用户确认：同一工程内聊天分支共享模型，新 worktree 才分出模型副本。已有独立工程不自动合并。

2026-09-23：新普通任务默认连接其 [文件夹工程](./FOLDER_PROJECTS.md)；零件子任务保持原 scope。旧独立工程仍通过显式邀请共享。

## 状态与入口

`workspace_id` 仍是调用任务 ID。`workspaces/<session>/binding.json` 显式绑定到工程所属任务，所有关联任务复用同一个后端。项目文档 `collaboration` 保存规范化工作目录、成员、各成员选区/撤销、逐对象单调版本、5 分钟写租约和一次性邀请。整份文档在原有工程锁内原子提交；相机和工具保留在各 UI 实例。共享工程的 widgetSessionId 同时含任务 ID，避免宿主复用另一个聊天的界面。

右键模型或列表 →「创建聊天分支」使用 app-only `studio_part_chat`，经已授权的官方 App Server 直接 fork、核验来源和目录、绑定指定零件；不向父任务发消息、不启动修缮回合。首次本地接入需人在 UI 开启。用户在对话中明确要求创建时仍可走原生 fork/invite/join。Git 子目录任务在原 cwd fork，协作归属项目根。

`invite` 要求工程版本和真实工作目录；`join` 校验一次性邀请、目录、零件版本和租约，拒绝覆盖已有目标工程。模型 `fork` 去掉协作成员信息，成为隔离副本。

## 编辑规则

- 人和 AI 都经同一 editor 事务；HTTP 头 `X-Studio-Workspace` 传聊天身份。缺少成员身份的共享写入拒绝。
- 推荐传 expected_versions。工程中其他零件改变不阻止当前零件提交；当前零件版本过期必拒绝，即使租约已经过期。
- 子任务只改绑定零件及派生件。整体替换工程在共享模式禁用。
- `replace` 将保留工程坐标的修缮文件替换一个原件；多网格成为派生件，首件保留 ID。支持任务产物的「替换选中零件」。
- 撤销保存当前会话的逐对象逆操作，不恢复整个工程快照。后续其他编辑使逆操作失效，不覆盖它；连续自身撤销/重做可用。
- 每次编辑持久化模型版本；活动共享界面每秒读取更新。属于有界轮询同步，不是逐帧广播拖拽过程。拖动时只本地预览，松手成功提交后同步。
- 租约默认 5 分钟，打开界面每分钟续自己的租约；菜单可释放。后台长操作应主动 renew；失联租约自然过期。租约不代替版本检查。

## XYZ 控件修复

导入的 GLB root 可能在 0，而网格顶点已在装配位置。TransformControls 改为绑定独立代理，其位置是零件世界包围盒中心。拖动产生世界增量，再乘原始对象世界矩阵并转回父级局部矩阵。几何资产、单位和装配位置不做重写。

## 边界

这是同一用户本机的协作冲突机制，不是隔离任意本地脚本的安全沙箱。直接修改 project.json 绕过工具不在契约内。共享的是模型编辑工程；打印计划、任务产物仍为工程资源。零件视图选区和镜头独立，不宣称整个打印/观察模块都按聊天隔离。

验证含纯数学偏置几何控件回归、双会话 MCP 绑定/冲突/隔离分支、持久化/租约过期/连续撤销/外部修缮替换，以及浏览器双界面同步。原生创建新聊天只在用户点击后执行，自动验证使用模拟宿主消息，不主动创建用户任务。
