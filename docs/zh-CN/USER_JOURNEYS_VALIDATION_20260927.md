## 本轮修复

1. **凹形色块碎裂。** 原实现逐三角形生成棱柱再布尔合并，经 GLB float32 回读后，
   有效十字色块被分成 9 块。现在按共享顶点和边界缝合一次构建闭合挤出体，再与
   原件求交；回归验证一个闭合连通嵌件及 1372.8 mm³ 体积，未丢弃碎片或放宽判定。
2. **交错编辑后的连续撤销误报冲突。** 同一会话编辑 A、另一个零件、再编辑 A，
   后续撤销 A 会被误判为他人修改。现在按零件寻找最近相关历史记录更新版本号；
   补了持久化重载后的撤销/重做和真正他人修改仍拒绝的回归。支架 MCP 流程还执行
   了 9 次交错撤销/重做。

## 尚缺什么，按建议实施顺序

| 优先级 | 实际缺口 | 影响与下一次验收 |
|---|---|---|
| P1 | 多零件加工结果不能原子替换多件原件 | 两个切开件的 `replace_ids` 被拒绝。本轮明确删除自己创建的两件后再导入；应补带 revision 校验的整体替换，保留无关对象并可一次撤销。 |
| P1 | 分色意图未传到打印耗材 | GLB 蓝/红正确，STL 副本丢失颜色，两盘 3MF 都是默认 `#00AE42`。目前需用户逐盘手动选色；应补零件/盘颜色清单和 3MF 材料绑定回读，不承诺自动 AMS 配置。 |
| P1 | 配方进度未接入加工任务证据 | 切割仍停在 `plane_cut`、分色停在 `color_split`、铰链停在 `pick_joint`。应绑定输入/输出版本及报告判定，不能只凭 task completed 标绿。 |
| P2 | 保存归档后的重开路径不直观 | 共享工程整体归档 `open` 按规则返回 `scope_violation`。保存成功，但应明确独立模型分支的恢复路径，保留协作保护。打开原目录工程与整体替换归档是两种操作。 |
| P2 | 默认渲染不能看清功能细节 | 正视/轴测装配图遮挡支架孔、长条销孔。应补顶视、剖视、爆炸图后再进行外观/配合验收。 |
| 后续证据 | 实体配合及宿主上手流程未测 | 需试片确认销孔间隙、嵌件保持、M2 五金安装、孔内支撑清除及强度；另测原生宿主 UI 和干净环境安装。数字检查不能替代这些。 |

铰链五金清单为一枚 M2×8 螺丝和一枚 M2 螺母。236 个拆装采样只检查打印本体，
**没有验证五金插入**。运动检查为离散采样，不保证连续运动无碰撞；分色报告也不
保证全模型最小壁厚。本轮未启动任何打印机。
