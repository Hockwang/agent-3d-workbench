# 完整城市工作台（v0.8.3）

> English: [../CITY_RUNTIME.md](../CITY_RUNTIME.md)

用户已确认 [完整城市联动方案](../history/CITY_RUNTIME_PROPOSAL.md)。支持附件
`cubely_lab_20260920.zip` 的固定源码契约，完整导入地形、道路、建筑、人物、设施和包内行为。
不需要额外 GPT API；在线 NPC 动作生成关闭。素材由用户在本机提供，不随插件提交或分发。

## 使用

1. 在独立项目/工作台进入「模型编辑 → 模型与对象 → 完整城市」，填入 Cubely ZIP 绝对路径并导入。
   AI 使用 `studio_edit(action="city_import", params={path:...}, expected_revision=...)`。
2. 城市在同一视口自动打开，默认暂停。列表搜索人物/设施，或点击场景中的可编辑实例；首次选择按需载入完整 GLB。
   AI 使用 `city_catalog(query,offset,limit)` 查实例，再 `city_checkout(instance_id)`。
3. 现有移动/旋转/缩放、材质、完整场景导出/回填继续可用。工作台仍为 mm、Z-up，城市内部为 m、Y-up。
   选区上下文包括编辑对象 ID、城市实例 ID、资产版本和动作绑定。
4. 「运行城市」恢复模拟，点击视口后 WASD 移动，E 车门，F 交互/上下车，C 切视角。
   暂停后继续编辑。运行中的位置是临时预览；持久化的是编辑布局、源资产和修改版本。
5. `scene_export` → 当前 GPT 操作本地 Blender → `scene_replace` 原位回填。
   保留人物原骨名映射和完整源动作。附件人物使用 30 fps；Blender 默认 24 fps 导出可能截短最后一帧。
   不兼容的骨架、缺失动作和截短时间轴会拒绝，旧对象保持不变。
6. 动作模式关闭城市预览，在同一个 renderer 中检查完整人物/设施的骨架与片段；回模型编辑点“打开城市”恢复全城。
7. 保存工程输出自包含 `.3dworkbench`，包括冻结城市包、实例清单、局部模型修改。
   导出 GLB/STL/打印需要显式选择已载入对象，不能把城市资源入口当成完整城市网格导出。

同工程零件聊天沿用 scope、租约、逐件版本和撤销；工作区分支沿用三方合并。
两个分支分别载入并改同一城市实例时，会拒绝重复绑定，要求解决冲突。

## 技术边界

- 共用 Studio 的 Three.js、WebGLRenderer 和 RenderLoop。关闭城市释放城市资源，不销毁宿主 renderer。
- 城市运行时负责米制相机的 near/far；宿主聚焦局部人物/设施时只调整位置与目标，
  不套用毫米网格的裁剪计算，避免远景地面深度冲突。见 [闪烁修复记录](../history/CITY_FLICKER_FIX_20260923.md)。
- 城市环境保持原分区、InstancedMesh、距离加载与设施 16 可见/22 驻留预算；全城资源入口只占一个工作台对象。
  精细编辑对象仍受 500 个上限约束，已编辑源 GLB 会增加内存，不是无限规模编辑器。
- 设施按实例换模，不污染同源模板；移动/形状改变重建独立 AABB 碰撞包络和空间索引，同步交互点，停止失效路径/召车。
  包络不等于凹面三角网格精确碰撞。改变原巡游设施的摆放后停止该实例原巡游，避免旧路线拉回原位。
- NPC 沿原行为系统活动和贴地；不是任意三维漂浮对象。兼容骨架可回填，任意换骨架/新语义映射还没有自动迁移器。
- 暂不支持城市实例删除/复制、直接 `motion_set`、道路拓扑或地形重塑；城市运行中选择与编辑需先暂停。
- 保存工程不保存一次驾驶的瞬间速度、剧情/集邮进度或跨窗口锁步模拟。
- 运行包约 480 MB，自包含工程约 336 MB，首次编译和载入需要时间。城市包冻结源码与资源哈希；其他版本 ZIP 若契约不同会明确报错。
- 导入只抽取源码、public 与 Rapier JS/WASM，不执行附件 npm 脚本/原生二进制。
  每次读取校验资源哈希并绑定当前工作台；归档恢复校验全部资源。动态脚本需本机显式导入时生成的信任收据。
  换电脑先从原 ZIP 在独立工程导入同版本，才允许打开对应归档运行模块。
- 运行预览使用内存存储，不依赖嵌入宿主的 localStorage/IndexedDB。基础走路/跑步由原包内动作提供。

实际验证、性能环境和限制见 [验收记录](../history/VALIDATION_20260923_CITY.md)。
