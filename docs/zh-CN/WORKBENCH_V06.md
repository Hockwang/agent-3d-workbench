# v0.6：模型编辑与打印准备

## 实现

`studio/core/editor.py` 使用 Trimesh / Manifold 实现静态网格操作；不重写几何内核。
工程位于 `<job>/workbench/`，原文件不改写，网格按 SHA256 存为不可变 GLB；`project.json` 原子保存对象、变换、可见性、选区与历史。
几何变更保留最多 30 个撤销状态；`save` 的 `.3dworkbench` 包含当前模型和选区，不携带整个撤销历史。

内部单位毫米、Z-up。标准 GLB/GLTF 导入按米/Y-up 转换，导出 GLB 时转回；STL/OBJ/PLY 默认毫米/Z-up，可在导入时选单位。
GLB/GLTF 的多层节点按世界变换展开为对象，保留几何及材质，不保留原父子层级；骨架、动画、形变目标输入会拒绝。
一般变换支持原贴图导出；切割、布尔、修复、拆组件、合并和减面输出纯色，贴图、多色或多材质输入需明确允许。

所有人工按钮及 AI 操作通过 `studio_edit`，必须带工程版本。旧版本修改返回 409，失败不提交工程状态。
输出不覆盖既有文件。`.3dworkbench` 读入核对资产 SHA、身份、矩阵与大小，不把 ZIP 路径直接解压到文件系统。

## 界面与打印衔接

- 右侧顶层切换模型编辑和打印准备；对话仍为轻量入口卡片。
- 模型编辑提供对象树、多选、变换控件、参数、切面预览、拆件/修复/材质页签、保存和导出。
- `studio_get_state.workbench` 是编辑状态，原顶层 `parts` / `selection.parts` 仍是打印状态。
- “将副本送到打印模块”显式创建世界坐标毫米 STL，再载入现有打印流程。STL 副本没有贴图；打印不会改变编辑资产。
- 可从已有打印零件生成编辑副本。打印状态与编辑状态不自动互相覆盖。
- 保留 HTTP 兼容界面；MCP iframe 通过资源读取 GLB，贴图来自内嵌数据，不向外网取图。
- 窄面板上下布局，参数独立滚动；收起工作区暂停 WebGL，重新打开复用对象与相机。

## 当前边界

- 适用静态三角网格，单对象最多 500 万面、工程最多 500 个对象。编辑预览使用实际网格，大模型所需内存和加载时间随面数增长；这不同于打印模块 3 万面显示预览。
- 切割/布尔要求有效闭合实体。平面未穿过实体会失败，不删除原对象。修复只覆盖法向、重复/退化面和小洞；输出仍可能有开口，会返回警告。
- 不提供面级刷选、自由曲线切割、SEG 服务、关节/蒙皮或生成 API。这些属于原规划后续批次。
- 当前项目存档保留几何、材质、对象变换与选区，不是 Blender 工程格式。
- 不推送实体打印。真实切片、Bambu GUI 和实物质量与编辑验证分开。

## 验证入口

```bash
uv run --locked pytest -m 'not bambu' -q
node --test tests/*.mjs
npm run build:app
```

`tests/test_editor.py` 覆盖切割实体/体积、失败回滚、版本冲突、带贴图 GLB 单位/坐标/名称往返、多选变换、隐藏导出、持久化与工程 SHA 校验、布尔/连通块、修复/减面、动画输入拒绝及 HTTP 来源/令牌。
`tests/test_mcp_server.py` 新增真实 stdio 测试：人创建 → AI 切割 → 人撤销 → GLB 资源读取与导出。

隔离浏览器宿主验证真实 MCP handlers 与嵌入 HTML；这不替代 Codex 原生右栏的可视验收。
自动 UI 工具不能操作 Codex 自身，安装后新任务才能可靠取得更新后的工具和技能。

2026-09-21 本轮结果：94 项 Python 测试通过，2 项 Bambu 实机测试未执行；14 项 Node 测试通过；MCP App 自包含构建成功。
隔离 UI 验证覆盖 420×700、420×420 和 900×840 宿主尺寸、带贴图 GLB、切割/变换、GLB 导出、打印副本交接和已有打印零件载入。
