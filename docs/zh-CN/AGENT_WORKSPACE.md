# 产品准则：让 AI 像写代码一样操作和验证 3D

2026-09-22 用户明确：日常看模型、观察和测评 WaveAB 新路线等工作，都应在 Codex 的这个工作台内完成。与外部同类产品的能力对照继续保留，但它不是产品边界。

## 每个能力都要形成闭环

1. **读状态**：对象、版本、单位、坐标系、选区、正在执行的任务都有结构化结果。AI 不需要靠截图猜控件或解析终端文本找路径。
2. **看证据**：模型要能直接返回真实观察图。只有包围盒、面数或“执行成功”不足以判断形状与动作正确。
3. **执行和接续**：现有工具能够完成的操作直接调用；开放式任务使用 Blender/Python/CAD。运行期间返回 ID，可查询、取消、查看失败记录；产物留在同一工作区继续处理。
4. **比较和验证**：版本对比共用相机和尺度，分别保留质量证据、运行耗时、Agent 用量和服务费用。未知项保持未知；不将观察图渲染耗时算成生成路线耗时。
5. **人在同一状态上接手**：常用操作通过选择和按钮完成，AI 与人使用同一后端。人工输入不被轮询覆盖，AI 选择的版本/姿态能在工作区显示，人的选择也可由 AI 读取。

成本看完成整个任务的消耗，而不是仅看工具调用次数。默认返回精简指标和一张总览，按需取单图、部件清单与日志；隐藏画面停绘，不同时常驻多套高面数模型。

## 选中即上下文

模型编辑或打印工作区的当前选区会成为下一条消息的 MCP 上下文。卡片标题显示「已选 N 件：名称…」，内容仅包含选中对象的 ID / 名称、尺寸、面数、job 与版本，不携带网格。编辑多选保留选择顺序；修改前 AI 仍需用 `studio_get_state` 核对最新状态。

- 初次空选区不创建附件；取消全部选择、删除全部选中对象，或切到没有零件选区的工作区时清除旧附件。
- 改名、尺寸与版本变化会更新快照；相同状态轮询不重复发送，用户关闭附件后不会被下一次未变化的轮询加回。
- 快速变化串行提交并合并中间状态，避免旧请求覆盖新选择。宿主暂时失败时，下次刷新重试。
- 本机 Codex 的 `ui/update-model-context` 扩展支持 `presentation.composerLabel`。清除请求使用 `content: []` 且省略 `structuredContent`；空结构对象仍会创建卡片。标准 MCP 内容与结构化数据保留，其他宿主的标题显示取决于其实现。

验证（2026-09-22）：前端 50 项、MCP / 工作区回归 34 项通过。使用实际发行 HTML、实际 Python MCP 处理器与隔离后端，在浏览器测试宿主里操作新建、改名、多选、缩放、取消和模式切换，回执与选区一致；测试未更改真实用户 job。标题与清除字段依据已安装 Codex 的 schema / 处理代码核验，浏览器测试宿主不等同于 Codex 原生输入框的视觉验收。

## 已接入：观察与测评

右侧新入口 `studio_open({mode:"observe"})`。`studio_observe` 共四个 action：

```json
{"action":"start","inputs":["/absolute/baseline.glb","/absolute/candidate.glb"],"labels":["基线","候选"],"params":{"views":["front","right","top","iso"],"phases":[0],"resolution":512}}
```

也可以用 `source_tasks:["任务 A ID","任务 B ID"]`，直接对照工作台已交付的模型并读取它们实测的 `elapsed_seconds`。两种来源互斥。每次最多四个版本；一个 GLB 或 URDF 表示一个完整版本，不能把四个零件误作为四条路线。

- `start` 非阻塞，复用持久任务执行器。已完成任务可用 `read` 取得报告；MCP 默认附真实 PNG `ImageContent`，不是把 base64 文本塞入上下文。
- `read({id,image:false})` 只取指标；`detail:true` 包含部件清单；`image_file` 可选报告列出的原分辨率单图。
- `focus({id,variant:0,phase_index:1})` 让人和 AI 聚焦同一个版本和姿态。省略 id 的 `read` 返回当前焦点。
- `review({id,expected_sha256,verdict,note})` 记录评价；`expected_sha256` 使用 `read.report_sha256`。理由必填，人工和 AI 来源分列，旧版本的评价不能自动套到新产物上。

模型读取复用 Trimesh；URDF 解析与正向运动学复用开源 yourdfpy，保留没有 visual 的中间 link。渲染复用本机 Blender，PNG 与交互预览都来自同一求值姿态。所有版本使用共同包围范围和相机，不分别居中或缩放掩盖尺度/位置差异。Blender 一次只常驻一个版本/姿态，避免多版本高面数模型叠加占用内存。

URDF 可指定 `params.urdf_up:"z"|"y"`；WaveAB 的部分产物为 Y-up，必须回源确认，不能仅凭 `.urdf` 后缀推断。STL/PLY 为毫米/Z-up，GLB 为米/Y-up。每份输入及 URDF visual 依赖保存 SHA256，观察结束检查未变；输出保存冻结的姿态 GLB、PNG、相机参数与 JSON 指标。模型文件本身不修改。

## WaveAB 路线评测的衔接

现有 WaveAB runner 和评测标准继续作为权威来源。AI 可以在 `studio_task` 的可信 Python 脚本中调用已有 runner，使用其真实参数，把 GLB 和运行报告交到任务 output；随后用 `source_tasks` 或产物路径创建对照。不得为接入工作台而复制另一套切割/关节求解路线。

本轮真实验收使用作者研究仓库中已有的 WaveAB 机器人、风车 URDF，验证产物读取、动作采样、证据与交互链。它不是新路线的质量或性能排名；未自动发起新的远端生成批次，也没有推断缺失的 token/费用数据。

仍待专项接入：任意研究目录/远端批次的一键发现、冻结评测协议和批量调度、带 GT 的质量度量、耗时/token/服务费用完整接入、连续碰撞/运动自然度检测。观察接口提供证据，不给没有标准的模型自动打“正确”分。
