# 配方

配方是一条穿过能力行的预设路线：走哪几行、每一行谁来定什么、过的标准看哪个数。
面板上看到的仍然是能力行和它们的数字；配方只负责把「想做成什么」翻译成「按什么顺序、在哪几处要停下来判断」。

**配方管「决定怎么做」，工具管「做并且验」。** 配方是数据，不含代码，也不能改变任何工具的行为。

格式的完整定义在仓库根目录的 `SPEC_RECIPES.md`，这里只讲怎么写、怎么装。

当前内置 18 条路线，17 条绑定本地能力，1 条为托管扩展。工具绑定可用不代表任意输入或实物验收通过。多数来自本项目既有配方，一部分串联现有编辑工具。
`workspace: "edit"` 的配方在模型编辑区运行；未指定时默认打印准备。编辑路线记录成功操作，
不会自动判定 guide 中的全部质量标准；换选区、撤销或其他几何修改后，相关步骤需要重新核对。

## 一个配方长什么样

```
recipes/<id>/
  recipe.json    路线：步骤、每步用哪个工具、预设入参、要定什么、过的标准、出处
  guide.md       判断点与踩过的坑，给 AI 和动手的人读
```

## 装一个别人写的配方

把整个目录拷到 `~/.print-prep/recipes/<id>/`（设了 `PRINT_PREP_HOME` 就是 `$PRINT_PREP_HOME/recipes/<id>/`），不用重启，
面板的配方抽屉和 `studio_list_recipes` 下一次打开就能看到，来源会标成「第三方」。

第三方配方只是文字。插件的硬规则——不发打印机、所有数字必须来自工具返回、不声称「已载入」——不因为任何配方而改变；
配方里预设的入参在装载时逐项校验，路径类的键一律不允许，所以配方没有办法让插件去读写它指定的文件。

## 什么该写成配方

| 情况 | 做成什么 |
|---|---|
| 单步、确定、输入输出清楚 | 工具。不要为它写配方 |
| 多步，但中间没有任何需要判断的地方 | 组合工具（例如 `studio_prepare`）；配方用 `one_shot` 指过去即可 |
| 多步，中间要看模型长相做判断，或者要人确认 | 配方 |

一个好配方的每一步都回答得出三个问题：这一步要定什么（`decide`）、看哪个返回字段的哪个数算过（`accept`）、不过怎么办（写在 `guide.md`）。
回答不出来的步骤，多半不该出现在路线里。

## 写的时候要守的

- `recipe.json` 的字段、长度上限和 `args` 的限制见 `SPEC_RECIPES.md` §1；装载时逐条校验，不过的配方不会出现在列表里，原因会列在抽屉底部。
- `steps[].tool` 写工具名，或者 `工具名#细粒度能力名`（比如 `studio_edit#split_components`、
  `studio_task#assembly-audit`、`studio_task#image-to-3d`）——真实工具的名字已经够粗，一个工具下面
  常常还有一整套动作/模板/操作没有单独建成顶层工具；`#` 后面那半就是引用其中一个。装载时会分别核对
  `#` 之前的工具是否存在、`#` 之后的能力名是否在那个工具当前的能力表里（`studio.core.capabilities`），
  两个都过才算「可用」，缺一个就进 `missing_tools`（原样带着 `#`）。内置配方应引用已实现的能力；
  工具绑定只说明调用入口存在，输入条件和验收仍须逐步核对。每一步除了 `tool` 之外，装载后还会多一个只读的 `call` 字段
  （`{"tool": ..., "action"/"template"/"operation": ...}`），照着它调用即可，不用自己再拆 `#`。
- `guide.md` 用固定的几节：什么时候用 / 什么时候别用 / 路线与判断点 / 我们踩过的坑 / 收口时告诉用户 / 出处。
  每一句都要能指导一个具体动作或一个具体判断；拿不准的数字不要写。
- `provenance` 必填：这条路线是从你自己的哪次工作里来的，或者依据的是哪份公开资料。
- 不要带进来的东西：别家产品的文档、提示词或脚本的改写；第三方角色、作品、商品的名字和由它们得到的样例；任何密钥、内网地址、本机路径。

## 已经接进来、但不是独立顶层工具的能力

下面这些能力已经有真实实现，只是没有单独建成顶层工具，写配方时用 `工具名#能力名` 引用：

| 引用方式 | 落在哪个真实工具 | 做什么 |
|---|---|---|
| `studio_edit#plane_cut`（兼容别名 `studio_plane_cut`） | `studio_edit` | 平面切割；手动选择模型和切面 |
| `studio_edit#split_components` | `studio_edit` | 按连通性把一个网格拆成若干实体件 |
| `studio_task#assembly-audit` | `studio_task`（本地模板） | 在显式给定的运动（旋转/平移范围）或 URDF 关节下，逐姿态采样精确实体相交，报交叠体积；不认"取出方向"这类装配序信息 |
| `studio_task#removal-audit` | `studio_task`（本地模板） | 沿取出方向离散采样装配/拆卸路径，判每一件能不能在不撞到别的件的前提下取出、装回，报装配顺序 |
| `studio_task#joint-coupon` | `studio_task`（本地模板） | 把配合部位（`compact_pivot`/`thin_slew` 等族）生成小试片 |
| `studio_task#<hosted-operation>`（比如 `image-to-3d`） | `studio_task`（托管服务操作） | 走用户自备的图生 3D 等托管服务；只有服务目录里声明过这个操作才算可用 |
| `studio_check`（可打印性闸门） | `studio_check` | 本身就是顶层工具：headless 试切，估重量/时长，不是逐件量壁厚 |

## 新补齐的本地能力

| 能力引用 | 输入条件与验收 |
|---|---|
| `studio_task#connect-parts` | 两个平面接合的闭合件；圆销/D 形销、盲孔、孔壁包络、离散拔出检查。 |
| `studio_task#color-inlays` | 单个闭合带色/贴图模型，明确调色板和共同拔出方向；闭合嵌件与主体、涂装提示、离散拔出检查。 |
| `studio_task#install-joint` | 两个主体、坐标架/锚点/加工区；销铰、回转、滑轨、分体球窝，加工件与新 URDF。 |
| `studio_task#motion-check` | 本地 URDF；有限笛卡尔网格或明确组合姿态的实体相交，最多 4096 姿态。 |

完整调用契约见 [PUBLIC_CAPABILITIES](../docs/zh-CN/PUBLIC_CAPABILITIES.md)。
任务成功后读取报告，导入或重载新输出，再继续打印流水线；配方不会自动执行这些步骤。
17 条配方具有本地工具绑定；`image-to-print` 使用托管扩展，不计入本地承诺。
配方 ready 不是任意输入已验收；物理保持力、强度、连续碰撞与任意语义拆件仍不属于这批数字工具的保证。
