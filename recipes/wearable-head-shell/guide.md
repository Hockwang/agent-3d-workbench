# 角色头壳制作

把已有静态角色模型做成可调头壳样稿。工作台内置配方调用 `shell-kit` 模板，随工作台分发；无需往个人 Codex skills 目录安装。

## 1. 输入与外观约束

在「选配方」启用「角色头壳制作」，上传一个静态 STL / GLB / PLY。先观察模型，核对朝向、尺度和连通部件。模板采用 Z 向上、脸朝 -Y；输入按总宽缩放，XY 居中、底面归零。其他朝向先在模型编辑中调整并导出。

记录头围、头部最大左右宽和前后长、头高、眼点及衬垫空间。只有头围时，允许先做声明假设的包络样稿，不能推出真人眼位或适配结论。模板中的 600 mm 头围、Ø6×3 mm 磁铁是可改初值。

默认保护原眼轮廓。保留嘴形，观察孔优先放在原黑眼内部；嘴缝、下缘等通风位置需按原造型标注。视线与造型冲突时记录待解决，先调整佩戴位置/尺寸；不得自动扩展内眼角。改变眼形需要用户明确允许。

STL 没有可恢复的颜色信息。独立部件可以保留并明确命名着色；部件索引、眼网等局部方案必须绑定 `source_sha256`。不提供任意贴图的自动语义分色。

## 2. 生成与改参数

在加工任务中使用「角色头壳 · 掏空与磁吸分壳」。调整总宽、壁厚、内壁采样间距、颈口宽深高、前后分界、接缝间隙、磁铁直径/厚度/对数及分色安装余量。`voxel_mm` 不得大于壁厚一半。闭合薄尖端可以保留实心。

高级 JSON 可声明 `head_envelope_mm`、`head_center_mm`、`mesh_eyes`、`eye_points_mm`、`smile_vents`、部件名称与颜色；坐标均为缩放归一后的模型 mm。它们需要逐模型观察与标注，不能套用另一角色的坐标。Pikachu 参数例见 `examples/head-shell/`，仅用于源文件 SHA 匹配的重现。

生成保留冻结的原输入。点击任务旁「修改参数」创建新版本；原任务和产物保留，流程检查自动指向新版本，外观确认重新进行。

## 3. 分别核对检查结果

- 几何与装配：每件正体积、水密、无实质干涉；装配路径为离散采样，仍需打印配合试片。
- 头部空间：只检查声明的头部包络，不代表真人适配或舒适度。
- 观察视线：核对暂定眼点的正前方射线和检查图；缺眼点、缺观察窗或被脸壳遮挡都保持待解决。采样通达不等于实测视野。
- 外观复核：点击「外观复核」生成同尺度来源/结果对照（AI 直接调 `studio_observe` 时，输入用产物 `inspection/source-reference/scene.glb` 与 `scene.glb`，不要用原始 STL——原始文件仍是源尺度，会渲成一小团）。查看眼形、白高光、嘴形和分缝。AI 评价与人工确认分开；人工对当前版本的 good 评价才推进外观步骤。

流程条可展开所有检查；即使视线待解决，也可先查看外观。绿色项只是各自声明的检查通过。

## 4. 交付边界

主 `scene.glb` 和根目录各零件 STL 用于装配/打印；`report.json`、`parameters.json` 记录参数与检查。`inspection/` 下原造型、内腔、头部包络和去网格视线资产仅供检查，不加入打印清单。

成品前仍需真人试戴、视野与通风核对、磁铁配合及保持力试片；大于打印床的半壳另做打印分块。报告保持 `wearable_ready=false`，配方完成也不代表已获可佩戴验收。
